# 安全模型

[English](security.md) | **中文**

> 状态：V1 已实现（2026-09）。硬不变量由 `pkg/*` 中的具名测试锁定，并在下方“硬不变量”一节以及 `architecture.zh-CN.md` 中重述。

Tokenhush 本身就是一个安全工具，因此**它必须先做到安全**。本文档定义威胁模型以及不可破坏的不变量。

## 威胁模型

| 威胁 | 描述 | 缓解 |
|---|---|---|
| **提示注入导致数据外泄** | 攻击者诱导模型输出占位符；如果网关在出站方向回填，密钥就会泄露 | **硬不变量：绝不向出站方向回填**（见硬不变量） |
| **本地恶意进程/网页访问网关** | 任何本地进程或浏览器页面都可以 `fetch` `127.0.0.1:8787` | 双栈环回（127.0.0.1 + `[::1]`）；`Host` 头校验；控制面额外要求每次 `run` 生成的 bearer token，以 `0600` 存于磁盘，并对携带 `Origin` 的请求做同源校验 |
| **DNS 重绑定** | 恶意域名解析到 127.0.0.1 以绕过同源 | `Host`/`Origin` 头校验 |
| **占位符冲突** | 两个密钥映射到同一占位符，导致错误回填 | HMAC 确定性映射 + 高熵后缀 |
| **审计日志篡改** | 事后编辑以掩盖泄露 | 具体存储委托给私有 Pro 层：仅追加 + HMAC 哈希链（密钥存于 Keychain / OS 密钥存储）。核心只定义仅元数据的接缝 |
| **从内存读取明文** | 同一用户下的另一进程调试或转储 | 沙箱/加固运行时；不向磁盘写入明文 |
| **供应链攻击** | 依赖被投毒（见 LiteLLM 事件） | 最小依赖 + 固定版本 + 签名发行版 + SBOM |

## 硬不变量

1. **绝不向出站方向回填占位符。** 回填只发生在返回给客户端的响应上。
2. **默认不存储请求/响应明文。** 审计接缝默认只记录元数据，且核心本身不存储任何审计数据。
3. **默认不安装根证书，也不执行 MITM。** MITM 在后续阶段是显式选择加入，且未在公开核心中实现。
4. **本地服务只绑定双栈环回（127.0.0.1 + `[::1]`）。**
5. **检测失败时失败安全（fail-safe），而非失败开放（fail-open）。** 当网关无法判断内容是否敏感时，它宁愿过度脱敏，或在告警下放行，绝不静默发出明文。该策略可配置（见下）。

> [!IMPORTANT]
> 不变量 1 正是提示注入无法把网关变成外泄通道的原因：占位符只在返回客户端的路径上被替换。

## 检测器取舍

- **假阳性（过度脱敏）** 损害体验：模型收到占位符，代码或回答质量下降。
- **假阴性（脱敏不足）** 损害承诺：敏感内容离开本机。

V1 策略是**确定性、高精度优先的检测器**（已知密钥前缀、高熵、JWT、私钥头、Luhn 卡号校验和以及电子邮件地址），辅以白名单与一键放行。本项目**不**声称“永不泄露”。诚实的说法是**“高置信密钥拦截 + 全程可审计”**。

## 审计接缝与完整性

- **接缝**：核心定义 `Record` / `Query` 以及 `AuditSink` / `AuditQuerier` 接口，并默认使用 no-op sink。私有 Pro 层注入具体存储。
- **存储与完整性**（Pro 层）：仅追加的 SQLite；每条记录的哈希包含前一条记录的哈希（HMAC 链），密钥存于 OS 密钥环。
- **内容**：接缝默认仅元数据（提供商、端点、时间、字节数、脱敏次数、敏感类型）。
- **保留**（Pro 层）：默认 14 天，建议范围 7 到 30，可配置。
- **诚实边界**：本地 HMAC 链无法提供第三方可验证的合规证明。不要对合规市场过度承诺。

## 密钥处理

- **V1：透传。** 工具携带自己的提供商密钥；网关只转发，**不存储**它们。
- 当多账号/路由（Pro）需要存储密钥时，它走跨平台密钥环抽象（macOS Keychain / Windows Credential Manager / Linux Secret Service 加一条回退链，该设计记录在私有 Pro 仓库中），并增加网关 token + Origin 校验以防止 CSRF。
- **诚实降级**：没有 OS 密钥环时，存储回退到受限文件（`0600`），并通过密钥存储的 `Backend()` **显式**报告，绝不静默。

## 发行与供应链

- **依赖审计**：核心只允许宽松许可证（MIT/Apache/BSD）；**禁止 GPL/AGPL**。
- **发行**：签名构建 + 校验和 + SBOM；CI 扫描依赖与密钥。
- **更新**：Homebrew / Scoop / `curl|sh` 签名分发。
